完整網站，逐步部署

將解壓後 SmartAction 資料夾裡的全部內容放到既有儲存庫的發布目錄，再用 Git 上傳。網站主頁、舊文章、資源、題庫與工具需要一起更新；只換一個 index.html，會缺少程式、樣式或模型。

本教學以 https://kuonanhong.github.io/SmartAction/、main 分支與儲存庫根目錄發布為例。附件已提供程式與部署材料；尚未替你修改線上的 GitHub 儲存庫、設定 Cloudflare 或開通付費行情。

2. 本機開啟：Mac、Windows、Linux

先將 ZIP 完整解壓，找到內含 index.html、assets/、blog/、assistant/、market/、tools/ 的 SmartAction 資料夾。不要在壓縮軟體的預覽視窗直接點 HTML。

部分靜態頁與小工具可以雙擊開啟；完整網站以 localhost 或 HTTPS 執行最可靠。AI 使用 JavaScript 模組、Web Worker 與模型檔，直接用 file:// 開啟不能完整運作。

macOS／Linux

安裝 Python 3 後，開啟 Terminal；將下面範例路徑改為實際解壓位置。macOS 可把資料夾拖入 Terminal 取得路徑。

cd "$HOME/Downloads/SmartAction"
python3 -m http.server 8000 --bind 127.0.0.1

Windows PowerShell

Set-Location "$env:USERPROFILE\Downloads\SmartAction"
py -m http.server 8000 --bind 127.0.0.1

若 Windows 沒有 py 而已有 python，可改用 python -m http.server 8000 --bind 127.0.0.1。Python 安裝網址：python.org。

保持命令列視窗開啟，瀏覽器進入 http://localhost:8000/；停止時在命令列按 Ctrl+C。網址應顯示主頁，不應顯示一長串資料夾清單。若出現清單，請再進入含 index.html 的資料夾後重開。

手機或平板請直接開啟已發布的 HTTPS 網站。上面的 127.0.0.1 只供本機使用，不會開放給其他裝置；也不能在手機輸入電腦的 localhost 來連線。正式功能驗證優先使用 GitHub Pages HTTPS 網址。

3. Git 上傳：保留原站與完整附件

git pull 是把遠端更新下載到本機；git push 才是把本機提交上傳到 GitHub。GitHub Pages 不會自動解壓一個 ZIP 來建立網站，因此要上傳解壓後的檔案。

3.1 準備 Git 與備份

安裝 Git 或 GitHub Desktop。以下指令使用你已有的儲存庫，不需要重新 git init，也不需要刪除原本網站。

如果電腦已有 SmartAction 本機副本，先把整個資料夾另存一份備份，包括尚未提交的改動。請勿直接把新包覆蓋在唯一備份上。也可先在 GitHub 儲存庫按 Code → Download ZIP 保存目前遠端內容；這不包含尚未上傳的本機檔案。

3.2 第一次在這台電腦下載儲存庫

macOS／Linux：

mkdir -p "$HOME/Sites"
cd "$HOME/Sites"
git clone https://github.com/kuonanhong/SmartAction.git
cd SmartAction
git status
git branch --show-current

Windows PowerShell：

New-Item -ItemType Directory -Force "$env:USERPROFILE\Sites"
Set-Location "$env:USERPROFILE\Sites"
git clone https://github.com/kuonanhong/SmartAction.git
Set-Location SmartAction
git status
git branch --show-current

若 Sites 內已經有 SmartAction，請使用既有副本，或另取資料夾名稱：

git clone https://github.com/kuonanhong/SmartAction.git SmartAction-20261009
cd SmartAction-20261009

資料夾名稱不同不會改變網站網址。如果現有分支不是 main，後面指令與 Pages 設定應採用你實際的發布分支；不要為了照抄教學而強制改寫分支。

3.3 既有本機副本先同步

git status
git pull --ff-only

先確認 git status 沒有尚待處理的修改。若有，請先備份並正常提交，或在獨立副本處理。--ff-only 會在本機與遠端歷史分岔時停止；看到停止訊息時，先檢查分岔內容，不要使用 force push 或 reset --hard 來跳過問題。

3.4 合併複製新包，保留未包含的舊文章

最容易的方式是開兩個檔案管理視窗：一個是「解壓後的 SmartAction」，另一個是「Git 儲存庫的 SmartAction」。把前者裡面的內容合併複製到後者，核對後替換同名檔案；不要把整個 SmartAction 資料夾再套進去，造成 SmartAction/SmartAction/index.html。

macOS／Linux 命令範例：先從儲存庫之外建立備份，再合併複製。下面備份名稱應選尚未存在的新名稱。

cd "$HOME/Sites"
cp -a "SmartAction" "SmartAction_backup_20261009"
cd "SmartAction"

# 把來源路徑改成解壓後的實際位置
SMARTACTION_SOURCE="$HOME/Downloads/SmartAction"
rsync -av --exclude='.git/' "$SMARTACTION_SOURCE/" ./

git status --short

此處沒有使用 --delete，所以新包沒包含的既有文章不會被批次刪除。若 Linux 未安裝 rsync，使用檔案管理器的合併複製即可。不要把解壓目錄與儲存庫目錄設為同一路徑。

Windows PowerShell 範例：

Set-Location "$env:USERPROFILE\Sites"
Copy-Item -LiteralPath "SmartAction" -Destination "SmartAction_backup_20261009" -Recurse
Set-Location "SmartAction"

$smartactionSource = "$env:USERPROFILE\Downloads\SmartAction"
robocopy "$smartactionSource" "." /E /XD .git

git status --short

robocopy /E 會複製子目錄，但不會刪除目標額外檔案；不要改成 /MIR。robocopy 的結束碼 0–7 通常表示完成或有檔案差異，8 以上需檢查失敗原因。以實際輸出與 git status 核對結果。

既有的 CNAME 是自訂網域設定；如你已使用自己的網域，請保留並核對。新包不會替你變更 DNS。.nojekyll 應在發布根目錄，避免靜態素材被 Jekyll 處理方式影響。

3.5 核對、提交、上傳

git status --short
git diff --stat

# 確認沒有密鑰、私人資料、額外 ZIP 或 node_modules 後暫存
git add -A
git diff --cached --stat

git commit -m "Update SmartAction knowledge portal and tools"
git push origin main

上傳可能要求登入 GitHub。使用 GitHub Desktop、Git Credential Manager 或已設定的 SSH／個人存取權杖即可；不要把密碼或權杖放在網址、HTML 或公開指令紀錄。不要把整個附件 ZIP 再放入儲存庫；網站需要解壓內容，重複放 ZIP 只會增加容量。

若 Git 顯示 Everything up-to-date，但你明明有新檔案，請檢查是否忘記 git add 或 git commit、是否站在錯的資料夾，以及是否改了正確的發布分支。

4. GitHub Pages 設定

  1. 開啟 kuonanhong/SmartAction 儲存庫。
  2. 進入 Settings → Pages。
  3. 在 Build and deployment 的 Source 選 Deploy from a branch。
  4. Branch 選 main，資料夾選 /(root)，然後 Save。
  5. 到 Actions 或 Pages 的部署狀態查看結果；等待顯示成功後，再開啟網站。
  6. 開啟 https://kuonanhong.github.io/SmartAction/，並檢查舊文章及新入口。

如果既有網站是從 /docs 或 GitHub Actions 發布，先保留原本流程並確認真正的發布目錄；不要只照本例改設定而讓舊工作流程失效。使用 /docs 時，應把整份網站內容放進 docs，而非根目錄。詳見 GitHub Pages 官方快速入門。

本網站使用相對路徑，適合 SmartAction 這種專案子目錄。大小寫在網頁主機上有差別；Assets 與 assets 不相同。直接改資料夾名稱後，所有相對連結與搜尋網址也要一起更新。

5. 模型、大檔與容量

5.1 為什麼不要只用瀏覽器拖曳上傳？

GitHub 官方限制：瀏覽器上傳單檔最多 25 MiB；一般 Git 對大於 50 MiB 的檔案提出警告，超過 100 MiB 的單檔會阻擋。本包模型含兩個 ONNX 檔，約 35.8 MB 與 59.3 MB，皆小於 100 MiB，但超過瀏覽器上傳限制，因此請使用 Git CLI 或 GitHub Desktop。

兩個權重精確大小可在 模型 manifest.json 查看；目前分別為 35,759,127 與 59,339,331 bytes。Git 出現大於 50 MiB 的警告時，並不等於這個檔案已超過 100 MiB 上限。參考 官方大檔說明。

5.2 Git LFS 無法解決 Pages 的模型載入

GitHub 官方明確說明 Git LFS 不能用於 GitHub Pages。本包的模型應以一般 Git 上傳。不要對 *.onnx 設 LFS，否則網站可能只下載到一小段 pointer 文字而不是模型。

# 在儲存庫中核對 ONNX 是否被誤設成 LFS
git check-attr filter -- assistant/models/flan-t5-small/onnx/encoder_model_quantized.onnx
git check-attr filter -- assistant/models/flan-t5-small/onnx/decoder_model_merged_quantized.onnx

若輸出是 filter: lfs，請先核對 .gitattributes 與本機是否持有真正模型檔，再修正追蹤方式；不要只重新命名副檔名。若未來改用超過 100 MiB 的單檔模型，應更換較小模型或改用允許大型二進位檔、提供正確 CORS 與 MIME 的資產主機，並修改模型載入與快取程式。單純把檔案切成幾段而不改載入器，也不會自動可用。

5.3 按需載入與十萬人容量

主頁不會自動下載模型。使用者進入知識助理並按「啟動本機模型」後，才會載入約 95 MB 模型權重及執行元件，首次合計約 120 MB；請以實際瀏覽器 Network 與 manifest 為準。只使用來源卡、閱讀文章與題庫的人，不必下載模型。

模型在訪客自己的 CPU／WebAssembly 執行，不會把每位使用者的推論計算集中到網站主機。但模型下載、網頁流量與瀏覽器記憶體仍有成本。建議使用桌面瀏覽器並預留約 1 GB 或更多可用記憶體；實际需求依瀏覽器、分頁與裝置而異，偵測到的 deviceMemory 不是精確剩餘 RAM。

GitHub Pages 目前發布站台最大 1 GB，每月頻寬有 100 GB 軟限制，也可能限流，不能承諾十萬人同時使用不當機。粗估十萬人各自首次下載 120 MB，約為 12 TB，遠超此月流量量級；這只是傳輸量算例，未計快取、壓縮、其他素材與重試。

若成長到大量模型使用者，需量測實際尖峰、把模型搬到允許且能承受流量的資產服務、確認帳單與授權，並保留來源卡的輕量模式。詳細限額請依 GitHub Pages 官方說明。

6. 商品、行情、AI 與小工具設定

6.1 公益商品與捐款

聰動消費與投資 已連到原網站使用的 協會綠界平台。帽子、馬克杯與衣服目前是可編輯概念目錄；未公告的售價及庫存不能補上猜測值。正式販售時，先由協會確認商品、價格、寄送、退換貨與收款，再更新 market/config.js 與平台連結。

Pages 不能主要作為電子商務或促成商業交易的網站。主站保持公益資訊與教育定位，實際商品、捐款及付款交給正式外部平台；若日後主要經營商城，應改用允許該用途的主機。網站意願清單只留在本機，不等於已送出的訂單。

6.2 全球行情與分析

附件提供 backend/market-worker/ 原始碼，但尚未部署。你可自行使用 Cloudflare Workers + Durable Objects 部署，再將服務網址填入 market/config.js 的 apiBase。先閱讀 完整行情與商品設定教學，按步驟建立服務、設允許來源、代碼清單、快取與配額。

供應商密鑰只能放在 Worker secret bindings；不要寫入 HTML、config.js、公開 Git 儲存庫或前端查詢網址。TWSE 每日成交資訊一律標示日終資料；Alpha Vantage／Finnhub 的即時、延遲與市场涵蓋範圍取決於供應商方案及再散布授權。未連接時顯示未設定，不會補上假行情。

即使不部署行情服務，也能使用官方交易所連結、下載後匯入 TWSE JSON、匯入 CSV 並計算過去資料的統計指標。這些指標不是買賣訊號；矽光子或先進封裝的重要性，也不能直接推導特定股票報酬。

6.3 本機生成式模型

知識助理 提供來源卡與隨包 FLAN-T5-small int8 ONNX 模型。卡片檢索與神經網路生成是不同功能：前者直接找已寫好的來源摘要，後者真正執行模型產生短答。生成部分目前以英文短答為驗證範圍，不宣稱能可靠回答所有語言。

小型模型可能誤述、漏答或不遵循來源；頁面保留來源卡供核對，醫療與投資重要資訊請使用原始資料。即使沒有付費 API，仍需下載時間、CPU、記憶體與電量。完整說明、授權與離線操作在 assistant/README.txt。

首次在線載入後，瀏覽器可保留快取，但系統可能清除快取。可靠的離線方式是保留完整資料夾，在斷網電腦用 localhost 提供檔案。按「停止」會終止模型 Worker；再次生成須重新啟動。不要把「首次在線下載後可離線」寫成「首次開啟完全不需下載」。

6.4 繪圖、簡報與影片工具

聰動小工具 是原創網頁工具，並未把所有 Windows 應用程式移植進網頁，也不是 Microsoft PowerPoint、專業影像編修或多軌剪輯軟體的完整替代。

簡報可新增、排序、播放與匯出 HTML／JSON／SVG／PNG；本版不匯出 .pptx。影片裁切透過瀏覽器重新錄製選定範圍，速度約接近片段實際長度，格式依 MediaRecorder 支援選擇 MP4 或 WebM；不是無損剪切。來源檔只在本機處理，未匯出的作品會在關閉或重新整理分頁後遺失。完整功能與限制見 tools/README.txt。

7. 多語與跨平台支援範圍

主入口提供 22 種語言的介面文字，保留手動語言選擇。初始語言依瀏覽器語言設定判定，而不是精確定位訪客所在國家；人在美國也可能使用繁體中文瀏覽器。瀏覽器語言選擇不需要取得 GPS 或額外的 IP 地理查詢。

22 種介面語言不等於全部醫療文章、外部影片與題庫都已有 22 種經專業審閱的譯文。市場與小工具目前有完整繁中／英文；助理来源卡與介面支援範圍另見專區說明。未支援的專區語言會回退到可用語言，不能把英文回退誤標為已翻譯版本。

對搜尋而言，完成且經檢查的翻譯應放在獨立網址，才配置對應 hreflang。不要為只有選單翻譯的醫療頁建立大量「完整外語版」宣稱。Google 建議明確語言網址與可切換入口，也提醒以 IP 強制改版可能造成抓取與使用上的問題。

現代 Windows、macOS、Linux、Android、iPhone、iPad 的瀏覽器能閱讀靜態內容；模型、影片編碼、檔案下載、Canvas、Web Worker 與快取行為仍有差異。這是一份跨平台網頁程式，不是所有硬體、所有瀏覽器版本及所有媒體格式均已實機驗證的保證。老舊或記憶體不足的手機可使用閱讀、題庫和來源卡，略過本地模型或大型影片。

8. SEO、AI 搜尋與真實點擊

8.1 關鍵字應出現在有用內容裡

適合自然使用的主題包括：巴金森氏症／帕金森病、Parkinson’s disease、高雄病友支持、照顧者、運動與復健、吞嚥與言語、非動作症狀、用藥衛教、聰動成長協會與非營利。關鍵是頁面實際提供相應知識，且名稱、背景、專業資格與合作關係均可核實。

標題、說明、段落標題、圖片替代文字與文章內文應各自清楚；不要塞入不相關詞、看不見的白字、超小字或重複堆疊關鍵字，也不要宣稱未經確認的醫院背書或專業認證。讀者看得見的專業解說、來源、更新日期及審閱者，才能累積信任。

8.2 以知識中心建立可連結的內容

  • 每篇文章解答一個明確問題，開頭先給簡明重點，再提供限制、可行步驟與原始來源。
  • 保留可引用的固定網址與章節錨點，讓題庫提示連到具體內容。
  • 將同題材文章、協會活動、可信資源與影片放在同一閱讀脈絡中。
  • 定期複核外部連結、醫療指南與日期，修正時保留說明。
  • 記錄真實作者與醫療審閱者；未安排審閱前，勿補造姓名、職稱或「醫師審核」標章。
  • 影片加入人工核對字幕、主題摘要與章節時間。未拿到字幕、影片畫面或可靠逐字稿時，不應猜測某句話位於第幾秒。

題庫來源按鈕可將長網址隱藏在有意義的文字後面，例如「查看運動建議」；這是介面呈現，原始網址仍可被瀏覽器查看。它不是加密、防作弊機制，也不應強迫觀看或自動開影片來湊點擊。讀者自願點擊、找到答案與重返網站，才是可持續的互動。

8.3 Google 與 AI 搜尋沒有神奇埋碼

Google 說明 AI Overviews 與 AI Mode 沿用基本 SEO 原則，不需要額外專用的 AI 檔案或神奇 schema 才能出現。可被抓取的文字、內部連結、良好體驗以及與可見內容一致的結構化資料更重要。llms.txt 若保留可當整理入口，但不代表 Google 或所有 AI 搜尋會使用，更不保證排名、引用或點擊。

請閱讀 本站編輯與來源政策，以及 Google AI 搜尋官方說明、Google 垃圾內容政策。

8.4 設定 Search Console 與 Sitemap

  1. 登入 Google Search Console。
  2. 新增 URL 前置字元 資源：https://kuonanhong.github.io/SmartAction/。你無法為不屬於你的 github.io 整個網域設定 DNS 驗證；有自己網域時才使用相應 DNS 網域資源。
  3. 按 Google 提供的方式驗證。若選 HTML 檔案，下載它給你的原始驗證檔，放到發布根目錄，git add／commit／push 後，確認該網址能讀取，再按驗證。不要自行編造驗證檔名或內容。
  4. 在 Sitemaps 提交 https://kuonanhong.github.io/SmartAction/sitemap.xml。
  5. 以 URL 檢查抽查主頁、知識文章及資源頁，查看抓取與索引狀態。
  6. 觀察曝光、點擊、點閱率與實際搜尋字詞，逐篇改進，不保證立即收錄或排名。

robots.txt 的生效位置是網域根目錄：https://kuonanhong.github.io/robots.txt。專案內 /SmartAction/robots.txt 並不等同網域根目錄的 robots.txt；若要控制爬蟲，應同時檢查個人網站儲存庫的根目錄設定，避免誤擋 SmartAction。

8.5 原網域與 GitHub 網域的重複內容

若 www.smartaction.org.tw 與 GitHub 網址長期放相同文章，應由網站管理者決定主要正式網址，再一致處理 canonical、內部連結、sitemap、結構化資料及可用的永久轉址。canonical 是選用網址提示，不保證搜尋引擎必定採用。

目前教學與新頁以 GitHub 網址為範例。若將來把正式網域指向 GitHub Pages，需先確認網域控制權、DNS、CNAME 與 HTTPS，再更新正式網址；不要把所有不同文章都 canonical 到主頁，也不要在同語文章中互相指定矛盾的主要網址。GitHub Pages 不能靠 .htaccess 設置任意伺服器轉址，請依實際 DNS、CDN 或主機能力設計。

頁面中增加領域連結不會自動換來外站推薦。可以用有品質的資源頁與協會活動成果，邀請真實合作機構在適當文章中引用；不購買垃圾反向連結、不製造隱藏點擊，也不自動播放或強制播放 YouTube 來灌觀看。

9. 持續更新與回復

日後每次修改先同步，再改檔、測試、提交。單純文章或介面更新不需要重做模型檔；避免每次重新下載或改寫大型權重，讓 Git 歷史不斷膨脹。

git status
git pull --ff-only

# 修改內容後，在本機預覽與檢查
git diff --stat
git add -A
git diff --cached --stat
git commit -m "Update reviewed Parkinson resources"
git push origin main

若剛發布的一筆提交造成問題，先看紀錄與差異，選擇要回復的那一筆：

git log --oneline -8
git show --stat COMMIT_ID

# 將 COMMIT_ID 換成已核對的實際提交識別碼
git revert COMMIT_ID
git push origin main

git revert 會新增反向提交並保留歷史；不是整個網站還原工具，也不能盲目對合併提交套用。若出現衝突，檢查衝突檔與備份後處理，不要為求快速而強制覆蓋其他人的修改。模型更新時也要更新相關快取版本，並核對 manifest、模型架構和執行元件是否相容。

建議維護紀錄包含：更新者、日期、醫療內容審閱狀態、來源變更、連結失效、功能問題與修正。題庫新增或改題時，一併檢查標準答案、選項唯一性、填空同義詞與提示來源。

10. 發布前後檢查清單

  • 主頁能開啟，標題、圖片、導覽與資料夾圖示清楚，手機不橫向溢出。
  • 原有幾篇文章與「更多文章」入口仍可讀取；文章不因合併更新而消失。
  • 資料夾入口能到市場、育樂、小工具、題庫與助理；育樂的三個外部網址正確。
  • 至少各試一題選擇與填空；正確／錯誤回饋、提示與來源按鈕都正常。
  • 抽查題庫中的醫療敘述及來源定位；沒有未核實的影片秒數或文獻頁次。
  • 切換繁中、英文和其他介面語言；回退語言的說明與實際內容一致，阿拉伯語版面沒有遮擋。
  • 商品仍未定案時，不出現虛構價格、現貨或已完成付款訊息；外部綠界網址正確。
  • 行情未設定時有清楚提示；設定後顯示真實來源、資料日期、抓取時間與時效，不把收盤資料標成盤中即時。
  • 匯入已知 CSV，核對至少一次區間報酬與最大回撤；缺資料时沒有殘留舊結果。
  • 小畫家能下載 PNG；簡報能新增與重開 JSON；影片短片能依瀏覽器支援輸出 MP4／WebM。
  • 知識助理第一次啟動有載入進度；來源卡、生成、停止及離線狀態正常。確認大型模型沒有被主頁自動下載。
  • 在 Chrome／Safari／Firefox 或實際目標手機抽測；瀏覽器不支援的功能有清楚提示。
  • 開啟瀏覽器開發者工具 Console／Network，沒有關鍵 JavaScript 例外、404、錯誤 MIME、LFS pointer 或被阻擋的必要資產。
  • 檢查 sitemap 中網址、canonical 與實際正式網域一致，且沒有把測試主機或 localhost 發布為正式網址。
  • 確認儲存庫沒有 API secret、個人病歷、付款資料或無意上傳的私人檔案。

附件測試僅代表已實際執行的環境與操作，不等於所有手機、全球網路、十萬同時訪客或外部金融服務均已驗證。請保留各專區的測試與 QA 說明以便後續維護。

11. 常見故障

看到的問題先檢查
主頁 404Pages 分支與根目錄是否正確；index.html 是否放在兩層 SmartAction 裡；部署是否成功；網址大小寫是否一致。
有文字，沒有樣式或互動是否只傳 HTML 漏掉 assets 或專區 JS/CSS；Network 是否有 404；相對路徑是否被改動。
更新後仍看到舊畫面確認部署成功與網址正確，再用無痕視窗或強制重新整理。助理如受舊 Service Worker 快取影響，可在開發者工具 Application 檢查站點快取；清除站點資料會同時清掉本機收藏與模型快取，操作前先匯出作品。
模型載入失敗必須用 HTTPS／localhost；模型與 vendor 是否完整；檔案是否被 Git LFS 轉成 pointer；網路、可用記憶體和瀏覽器 WASM 是否支援。
模型生成慢或答非所問先用來源卡。CPU 速度、問題長度與瀏覽器限制會影響延遲；77M 小模型能力有限，停止後可釋放記憶體。
行情提示未設定或 CORS未部署 Worker 時屬預期狀態；依市場教學設定 apiBase 與 ALLOWED_ORIGINS，或匯入官方 JSON／CSV。不要把 API 密鑰改放前端來繞過問題。
行情 HTTP 429／額度不足等待、減少查詢、核對供應商額度與 Worker 配額；不要取消所有限制或無限重試。
YouTube 無法頁內播放檢查瀏覽器、網路、地區與影片是否允許嵌入；改按原始影片連結開啟。不可保證任何限制中的影片都能在本站播放。
影片不能輸出特定格式使用瀏覽器實際支援的 MP4／WebM；不要只改副檔名。保留分頁在前景，先用短片測試；某些手機或編碼可能不支援。
超過 100 MiB 無法 push找出被拒絕的單檔；本包兩個模型都低於上限，常見原因是額外 ZIP、安裝檔或影片。若大檔已進入未推送提交，單純刪檔再新提交不會移除歷史；先備份，按官方大檔修正文件處理。
